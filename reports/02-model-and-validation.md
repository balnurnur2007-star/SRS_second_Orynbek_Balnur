# Отчёт 2. Модель данных и валидация

**Тема:** «Мобильный интернет-трафик — MobileUsage»

**Этап:** 2 из 5

**Дата выполнения:** 13 октября 2026 года

## 1. Цель работы

Создать класс `MobileUsage` для хранения одной ежедневной записи об использовании мобильного интернета и Wi-Fi. Добавить проверку всех значений, чтобы некорректные данные не попадали в программу.

## 2. Реализованный класс

Файл: `src/main/java/model/MobileUsage.java`.

Класс содержит четыре закрытых поля:

| Поле | Тип | Описание |
|---|---|---|
| `date` | `String` | Дата в формате `ДД.ММ` |
| `dayType` | `String` | Тип дня |
| `megabytes` | `int` | Мобильный трафик в МБ |
| `wifiHours` | `int` | Время в Wi-Fi, ч. |

Также реализованы конструктор, геттеры, сеттеры и метод `toString()` для удобного вывода записи.

## 3. Валидация данных

Проверки выполняются в сеттерах, поэтому они работают и при создании объекта, и при последующем изменении данных.

| Поле | Условие корректности | Действие при ошибке |
|---|---|---|
| `date` | Формат `ДД.ММ`; день от 01 до 31, месяц от 01 до 12 | `IllegalArgumentException` |
| `dayType` | Строка не пустая и не состоит только из пробелов | `IllegalArgumentException` |
| `megabytes` | Значение от 0 до 100000 | `IllegalArgumentException` |
| `wifiHours` | Значение от 0 до 24 | `IllegalArgumentException` |

## 4. Пример корректной записи

```java
MobileUsage usage = new MobileUsage("12.10", "оқу күні", 1500, 6);
```

Результат: создаётся запись за 12 октября, с 1500 МБ мобильного трафика и 6 часами Wi-Fi.

## 5. Примеры некорректных данных

```java
new MobileUsage("12/10", "оқу күні", 1500, 6); // неверный формат даты
new MobileUsage("12.10", "", 1500, 6);         // пустой тип дня
new MobileUsage("12.10", "демалыс", -1, 6);    // трафик меньше нуля
new MobileUsage("12.10", "демалыс", 500, 25);  // Wi-Fi больше 24 часов
```

Во всех четырёх случаях программа останавливает создание неправильной записи и выводит понятное сообщение об ошибке.

## 6. Тестирование

Создан файл `src/test/java/model/MobileUsageValidationTest.java`. Он проверяет:

1. сохранение корректных данных;
2. отклонение неверного формата даты;
3. отклонение пустого типа дня;
4. границы для мобильного трафика;
5. границы для времени Wi-Fi.

При успешном запуске выводится сообщение:

```text
Проверка MobileUsage успешно пройдена.
```

## 7. Вывод

На втором этапе создана модель данных `MobileUsage` с защитой от неверного ввода. Теперь программа готова к добавлению правила `isHeavyDay()` на следующем этапе.
